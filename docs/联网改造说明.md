## 三、部署三步

1. 上传 `server/` 到网站根目录，访问 `/server/install.php`
2. 填数据库与管理员账号，点安装（自动建库建表、生成配置、上锁）
3. 打开 `index.html` 即可

前端默认连 `server/api/index.php`（同域相对路径）。服务端放在别处时，改 `js/net/api.js` 第 14 行的 `BASE`。

**验证安装是否成功**：浏览器打开 `你的域名/server/api/index.php?action=ping`，应返回
`{"ok":true,"data":{"time":"...","version":"1.0.0","php":"8.2.x"}}`。

## 五、几个关键技术决策

**为什么用预置文案替代 UGC**
自由文本一旦上线，就要配审核队列、敏感词库、举报入口、人工复核。现在玩家从 32 条遗言 / 24 封信 / 16 条回应 / 12 句辩护词里选一条，服务端只记 `line_key`。仪式感一点没少，风险归零。

**为什么音效用合成而不是 mp3**
一是"开箱即用"——音频路径写错就是 404 一片；二是体积 0；三是每一次掷骰的撞击声都带随机扰动，听一百次不腻。

**为什么全部用运行时包装而不改原模块**
原 24 个模块是压缩代码机械还原的，改一行就可能踩到短变量名的语义。所以 `94-online.js` 只做 `wrap('qx', ...)` 这类包装：原函数照原样跑，包装层只加副作用。所有 hook 都包了 try/catch，联网出问题不影响本体。

**为什么离线要降级**
`file://` 双击打开、后端没装、服务器挂了——三种情况都会让 naive 的 fetch 抛错并中断初始化。现在 `NET.probe()` 一失败就标 `offline`，全部玩法面板弹"需要先登录"，游戏本体照常。

钟面在 `C.day` 变化时才重绘，不是每帧画。

内容来自 `life_ads` 表，走 `action=ads.list` 拉取，公开接口不需要登录。改完后台
刷新即生效。后台 → 广告位。

三个坑记一下：

1. **贴图不能一上来就铺内置文案**。`js/net/api.js` 排在所有游戏模块之后，
   请求要等 three.js 那 488KB 解析完（实测约 1.9 秒）才发得出去。所以给接口
   2.6 秒窗口期，拿不到再铺内置——否则会白建 12 张 512×768 贴图（约 15MB 显存）
   并且永远留在缓存里。
2. **圆盘原来只比草地高 0.025 米，深度缓冲精度不够会被草地整块盖住**（实测整个
   中央变绿）。现在圆盘 0.06 / 地纹 0.10 / 地贴 0.13，分层清楚。
3. **three.js 的打包产物没有导出 `Raycaster`**，广告点击用投影近似：把面板中心
   投到屏幕，按「米 → 像素」算命中半径。另外 bundle 里也没有 `PlaneGeometry`，
   已在导出表补上（`PlaneGeometry:Eo`）。

### 7.1 埋点只做一件事

`js/net/track.js`，三套场景都引（`index` / `difu` / `tiangong`）。等 `load` 之后
800ms 发一次 `visit.hit`，`keepalive`，失败静默。上报字段只有访客指纹、场景名、
时区、语言、屏幕、来源域名——**没有任何游戏内容**。

关掉的方式是服务端开关 `feature.track = false`，前端不用动。

### 7.2 地区判定：为什么自带一张 1.2MB 的表

「覆盖地区」「访问地区排行」绕不开 IP 归属。三种做法比过：

1. **调用在线 IP 接口** —— 每次访问多一次外部请求，玩家隐私和可用性都不可控，否掉。
2. **按 /16 归并成 323KB** —— 表小，但实测省级准确率只有 **92.6%**。
   中国早期分配区（如 1.0.0.0/16）同一个 /16 里混着泰国、澳洲、福建、广东，
   取占比最大者会系统性把用户判错，排行榜会显得很假。
3. **中国段保留原始边界 + 境外按 /16 归并** —— 41,108 段 / 1.2MB，
   省级准确率 **99.9%**，查询 200 次 0.7ms。最终选这个。

数据来自 ip2region v1.9.0 的 `ip.merge.txt`（Apache-2.0），生成脚本一次性处理，
产物是 `server/lib/geoip_data.php`，**不需要服务器装任何扩展**。IPv6、内网、
查不到的地址用前端上报的时区兜底。

这张表只在 `visit.hit` 里 `require`，后台和其他接口都不加载它。

### 7.3 几个取舍

- **PV 不去重、UV 靠 vid**。刷新一次记一次，但访客指纹 30 天轮换、同一 IP 10 分钟
  最多 90 次，刷量成本不低。UV 是「设备维度」的近似。
- **资产排行用 `MAX(lives.money)`**，不解析 `saves.state` 的 JSON。后者是 LONGTEXT，
  用 `JSON_EXTRACT` 在大表上没索引，为了一个榜单不值得。
- **积分排行只算 `closed=1`**，跟游戏内的 `rank.list` 保持一致。
- **缺表必须能降级**。老库没有 `visits` 表时，数据概览会显示一行提示加一个
  「去修复数据表」按钮，而不是抛 PDO 异常白屏。

### 8.2 三个设计上的坑

**坑一：金额量级差 30 倍。** 原有事件库的损失中位数是 -60 块，新写的是 -4500。
直接塞进去，一局必死。写了模拟器跑 400 局验证：原权重下平均活 47~88 天，加进去掉到 24~56 天。

修法两步：

1. 把「坏事 / 职业坏事 / 链式」里所有 `|m| >= 2000` 的绝对金额（161 处）改成比例扣款
   `pct: -0.30 ~ -0.80`，实际扣 `(max(0, 钱) + 800) * pct`。写死「-45000」，前期一局必死、
   后期不痛不痒；写成比例，痛感才前后一致。叙述里写死金额的 9 处也一并改写
   （「你算了三遍，一万四」→「没敢再算第四遍」）。
2. 体力 / 精神负值打阻尼：`st × 0.7`、`sp × 0.82`（572 处），
   把 `stAvg` 从 -7.9 收到 -5.6、`spAvg` 从 -4.9 收到 -3.3（原库是 -4.5 / -3.4）。

**唯一例外是中奖**：一等奖 1080 万用定额 `amt` 写死，不吃任何加成——
一夜暴富就该是绝对数，按比例写穷人中了没感觉。

**坑二：牌堆条数会决定出场率。** 如果 8 个牌堆一起抽，
条数多的堆（比如好事 27 条）会碾压条数少的（职业好事 38 条摊到每个职业只有 2 条）。
所以改成**两段式**：先按权重抽牌堆，再在牌堆内均匀抽一条。

权重表在 `js/life/87-turn.js` 顶部：

```js
var YW = { job: 24, season: 15, common: 17, weather: 13,
           good: 9, bad: 9, jobGood: 3, jobBad: 3 };   // 合计 93
```

试过 36 / 32 / 27 / 24 四档，最终定 24。实测平均存活天数只掉两成，
最优决策模式下基本持平——好事补体力能对冲坏事的消耗。

**坑三：同一个梗连着来。** 加了 26 条标题的记忆（`C.usedEv`），命中就重抽，
最多 26 次。所以「中奖」「车祸」这类大事件不会连着两天刷到。

### 8.3 链式事件：让一件事有后半段

买了彩票不能当场开奖，牙疼要等复发，股票跌了要等第二天继续跌。写法：

```js
chain: { after: 2, roll: [["lot_big", 0.008], ["lot_mid", 0.06],
                          ["lot_small", 0.22], ["lot_none", 0.712]] }
```

`after` 是「再踩几次事件格之后唤出」，`roll` 是按概率摇后续。队列存在 `C.chain`，
最多 4 条，每次踩事件格先 `--after`，归零就唤出，且优先级高于当次抽签。

一等奖概率 0.8%，扣完税 860 万——**够在后面几十天里随便挥霍，也够一次踩雷全赔回去**，
这正是想要的曲线。

### 8.4 三界判定

一世走完时判一次：

- 做过恶事（`C.evil >= evil_need`）→ 进 `difu.html`
- 一件没做过 → 进 `tiangong.html`

判定成功时结局卡上插入一块面板，8 秒倒计时自动跳转，可点「留在这一世」取消。
跳转地址带上整世履历（死因、天数、职业、善业、恶业、余财、精气），
两个场景页由 `js/net/realm-gate.js` 接住，在页顶浮一块「接引牌」说明你为什么在这儿，
并给一个「回阳世」按钮——**不让玩家困在这两个场景里**。

五个参数全在后台 → 系统设置 →「三界判定」里改：启用开关、入地府概率、上天庭概率、
恶业阈值、慈悲线（善业减恶业达到 N 可改判天庭）。改完立即生效，前端每次进游戏拉一次
公开接口 `realm.config`。

**拉不到怎么办**：接口挂了、表不存在、断网，一律保持默认值（全 100%），
结局流程照常走，不会白屏。

### 8.5 这轮踩到的坑（留给以后）

- **事件重名会让其中一条永远抽不到**。去重是按标题做的，写了校验脚本 `check-fate.js`
  扫全库，查出 3 处撞名（「房租要涨了」撞了理发师的职业事件）并改掉。
- **结局卡按钮被压成 56px**：`.ov-card .btn { width:100% }` 覆盖了 flex 布局，
  加 `width:auto` 修好。这个教训是：模块里已有的全局选择器，新组件一定要验一遍宽度。
- **接引牌挡住主按钮**：初版 `top:72px` 压在标题上，改 `bottom:86px` 又挡住「入幽冥」。
  最终是 `top:78px` + **等入场页 / 载入页消失后才挂载**，入场页只插一行灰字。
- **天庭页的牌永远不出现**：它用的是 `type="module"` + three.js，载入页要等
  `buildScene()` 才隐藏，慢的时候十几秒。原来「无限等载入页消失」的逻辑等于把牌锁死了。
  改成「先入 DOM、暂隐藏、就绪即显，载入页最多等 15 秒」。

## 九、命运扩展与三界审判（追加）

上一版只有"事件库 + 死后分流"。这一版把善意恶业真的做成了可玩的东西，一共 14 条。

### 9.1 新增文件

```
js/life/66-events-retribution.js   报应牌堆（恶业 ≥3 才开）
js/life/95-fate-extra.js           改命 / 卜卦 / 图鉴 / 墓志铭 / 善业挡灾 / 头顶气象
js/life/96-run-mod.js              命运卡组 / 每日一命 / 善恶天平 / 因果债
js/net/realm-trial.js              孽镜台 / 孟婆汤 / 六道轮回 / 天庭受封
```

四个文件都不改原模块，全部在加载时包一层。`index.html` 只是多引两个 `<script>`，
`difu.html` / `tiangong.html` 各多一个。

### 9.2 核心循环的四改

| 玩法 | 接在哪 | 为什么接在这儿 |
|---|---|---|
| 改命（恶业换重掷） | 包 `xu()`，支持传指定点数 | 掷骰只有一个入口 |
| 善业挡灾 / 替身 | 包 `ds()` | `r_` `qx` `Eu` 三条路径都走 `ds()`，拦一处就够 |
| 报应牌堆 | 改 `Yx()` 的 bands 数组 | 权重集中在一处，加一档就行 |
| 头顶气象 | 挂在 `xe` 上，独立 rAF | 不占主循环，掉帧也不影响玩法 |

**改命是这一批里最值钱的一条。** 恶业原来是纯减分项，玩家做坏事没有即时收益，
只有一个"死后才算"的远期惩罚。改成可消费之后，每个"坑同事一把"的选项都有了诱惑；
再用「恶业压低好事权重 + 恶业开报应牌堆」两个刹车把它拉回策略而非必胜。

### 9.3 三界审判的流程

```
结局卡 → 三界判定（realmJudge）
   ├─ 入地府 → 孽镜台（逐条辩恶事）→ 孟婆桥（选浓度）→ 六道轮回（选出身）
   └─ 入天庭 → 受封（选仙职）
                ↓
        localStorage.life_next_v1
                ↓
        index.html 开局时读一次、用完即删
```

**为什么用 localStorage 中转而不是 URL 参数**：这一份数据有嵌套结构（bonus 三个字段），
拼进查询串要序列化两次，还容易被玩家改。localStorage 同源、跨页面可见、天生带 TTL 语义
（我们自己判 24 小时）。

**为什么孽镜台只审恶事**：好事不用审。让玩家逐条回忆自己做过的坏事，比看一行
"你做过 4 件恶事"有效得多——尤其"辩"这个动作，消耗的是真金白银的善业。

### 9.4 踩过的两个坑

**① 继承的时机错了，钱被吞了**

第一版把 `applyInherit()` 放在 `Dc()` 包装的最外层，结果点「就这样走」弹出卡组面板时
就执行了一次：3000 块加到 `C.money` 上，然后玩家选完卡、原始 `Dc()` 一跑，
`C.money = t.money` 直接覆盖，钱没了，`life_next_v1` 也被删了。

改成 `if (C.started) applyInherit()`——原始 `Dc()` 会把 `C.started` 置真，
所以只有真正开局那一趟才继承。

**② 每日一命的种子会被 `await` 打断**

一开始想用"预生成事件序列"实现，写了一半发现 `Yx()` 要处理去重、链式、权重，
预生成等于重写一遍。后来改成在 `Gx()` / `Yx()` / `Lc()` 三个函数执行期间临时替换
`Math.random`（`try/finally` 还原），只改这三个入口，别的地方（three.js、UI 动画）
不受影响。

牌序是固定的，但抽到第几张取决于玩家走了多少步——这正是 Roguelike 日赛该有的样子。

### 9.5 后端三张新表

`life_karma_log` / `life_debts` / `life_codex`，都是 `CREATE TABLE IF NOT EXISTS`。
老库在后台跑一次「修复数据表」即可，不动已有数据。

### 9.6 一句话总结这 14 条的共同点

**都在把"已经存在但没用起来的数据"变成玩法**：

- `C.deeds` 原来只存 12 条、只在结局卡显示三条 → 孽镜台逐条审
- `C.good` / `C.evil` 原来只在死时算一次账 → 改成可花（改命）、可保命（挡灾）、会反噬（报应）
- `C.chain` 原来只服务彩票和病情 → 拿来塞因果债
- 332 条事件原来抽完就忘 → 图鉴收集
- `YW` 权重原来是常量 → 被全服善恶总量实时调制

## 十、已知限制

1. **后端已在 MariaDB 10.6 上实测，MySQL 5.7 未实测**。本轮拉了一个便携 MariaDB，跑通了：29 条建表语句 / 25 张表零缺失、`visits` 表缺表与补建两条路径、`visit.hit` 真实写入、数据概览页完整渲染（含截图核对）。SQL 全部按 5.7 语法写（唯一键 varchar(191)、不使用窗口函数、`GROUP BY` 满足 `ONLY_FULL_GROUP_BY`），但请仍以部署后的 `?action=ping` 自检为准。
2. **`lifeloan`（借寿）默认关闭**。它是纯正的东方神话经济，但平衡性风险大，`config.php` 里改成 `true` 才开。
3. **古井存档恢复依赖游戏状态字段**。`Sync.restore()` 已经用 try/catch 兜底，字段对不上时会提示"只能重开"，不会白屏。
4. **AI 专属结局只留了接口**。`server/api` 没有接 LLM——需要你填一个可用的 API Key，涉及密钥托管，我没擅自写死。
5. **三界判定在前端做**。`realmJudge()` 跑在浏览器里，改代码就能绕过。这是有意的：
   它是叙事分流，不是结算发奖，玩家真想去天庭逛一圈也没必要拦。概率规则由后台下发，
   作用是把「多少个恶人下地狱」变成运营参数，而不是防作弊。
